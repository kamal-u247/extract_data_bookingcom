## Event Lifecycle Rules

1. **Plan added** — Append when a new plan is defined and added to [FUTURE_PLAN.md](./FUTURE_PLAN.md).
2. **Work started** — Append when a developer is assigned and starts implementation work on a dedicated branch.
3. **Daily commitment / Progress** — Append day-to-day progress, milestones, blockages, or daily developer commitments.
4. **Implementation completed** — Append when feature work and pull request implementation are completed.
5. **Plan completed** — Append when implementation is verified and merged.
6. **Immutable History** — Never edit or delete existing timeline rows. Always append new rows for updates, changes, or status shifts.
